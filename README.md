# Астрономический календарь

Настольное приложение (Windows 10 x64, Python 3.11, PySide6) для расчёта и просмотра астрономических
событий. Расчёты выполняются локально по эфемеридам JPL (Skyfield); интернет нужен только для
скачивания эфемерид и поиска координат по названию.

**Версия 0.1.0 — MVP (приложение А ТЗ).** Статус по этапам ТЗ — внизу.

## Быстрый старт (Windows, VS Code)

```bat
py -3.11 -m venv .venv
.venv\Scripts\activate
pip install -r requirements-dev.txt
python main.py
```

1. Откройте раздел **«Обновление данных»** и нажмите «Скачать / обновить эфемериды» (≈ 32 МБ, один раз).
   Либо положите файл `de440s.bsp` в `resources/ephemeris/` вручную
   (<https://naif.jpl.nasa.gov/pub/naif/generic_kernels/spk/planets/de440s.bsp>).
2. В **«Настройках»** выберите место наблюдения (по умолчанию — Москва).
3. Проверка ядра без интерфейса: `python scripts/check_core.py`.

В VS Code: `Ctrl+Shift+P` → *Python: Select Interpreter* → `.venv`; запуск — F5 на `main.py`.

## Тесты

```bat
python -m pytest
```

Тесты расчётов сверяются с независимыми справочными значениями (равноденствия и солнцестояния 2024,
фазы Луны, противостояния Сатурна/Юпитера/Марса, лунные затмения 2025 и т. д.) и **пропускаются, если
нет файла эфемерид**. Тесты БД, часовых поясов (включая переходы на летнее время), некорректных
координат, ошибок API и отсутствия интернета работают без эфемерид.

## Сборка EXE

```bat
build_exe.bat
```

Результат — папка `dist\AstronomicalCalendar\` с `AstronomicalCalendar.exe`; Python на целевом
компьютере не нужен. Если `resources\ephemeris\de440s.bsp` лежит в проекте при сборке, он попадёт в
EXE, и программа заработает без интернета с первого запуска. В собранной версии БД, логи и скачанные
эфемериды хранятся в `%APPDATA%\AstronomicalCalendar`.

## Модель расчётов и ограничения

* Эфемериды JPL DE440s (1849–2150); положения «apparent» (световое время, аберрация, отклонение света).
* Время — UTC, отображение — в часовом поясе выбранного места (`zoneinfo`, на Windows нужен `tzdata`).
* Восход/заход: Солнце и Луна −0.833°, планеты −0.567° (стандартная рефракция), без учёта рельефа и погоды.
  Высота в таблицах — с учётом стандартной атмосферы (10 °C, 1010 мбар).
* Блеск планет — приближённые формулы Astronomical Almanac (≈ 0.1–0.3ᵐ; у Сатурна кольца не учтены).
* Соединения/противостояния — по эклиптической долготе относительно Солнца.
* Лунные затмения: тип и момент максимума; фазы и величина не рассчитываются.
* Метеорные потоки: даты максимума округлены и могут отличаться на 1–2 дня.

## Структура

```
main.py            точка входа
config/            пути, настройки по умолчанию (settings.json)
ui/                страницы PySide6 (без вычислительной логики)
astronomy/         время, координаты, Солнце, Луна, планеты, затмения, метеоры, видимость
api/               HTTP-клиент, геокодирование, загрузка эфемерид
database/          менеджер SQLite и модели
services/          события, кэш, обновления, данные главной страницы
tests/  scripts/   тесты и проверка ядра
```

UI обращается к расчётам только через `services/` и `astronomy/`; тяжёлые операции выполняются в
фоновых потоках (`ui/workers.py`).

## Важно знать

Этот код был написан в среде без доступа к PyPI и серверам NASA, поэтому тесты с Skyfield и проверка
PySide6-интерфейса там не запускались. Они выполняются в CI (`.github/workflows/ci.yml`, Windows,
Python 3.11) и у вас локально — первым делом запустите `python -m pytest` и `python scripts/check_core.py`.
